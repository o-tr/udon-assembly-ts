# Mahjong Lightweight Optimizer Plan

## Scope

Improve optimization effectiveness for very large `../mahjong-t2` TAC while keeping optimizer completion. Current large-input guards prevent SCCP/CFG/liveness-heavy passes from timing out or OOMing, but also skip optimizations that would help the biggest generated methods. Focus on a staged optimizer pipeline: converge lightweight/local passes first, then conditionally attempt heavier global/fixpoint passes only when the reduced input is genuinely small enough.

Repository rule context: `docs/coding-agent/rules/index.md` is absent, so validation is selected from project commands and bounded `../mahjong-t2` profile runs.

Research waived: subagent use is not authorized by the user/tool policy. The Orchestrator will inspect and profile locally.

## Progress Log

- 2026-05-29: Plan created after user requested continued optimization effectiveness, not only completion.
- 2026-05-29: Added block-local copy propagation and overwritten pure producer elimination as lightweight fallbacks when global copy propagation/dead-store liveness are skipped.
- 2026-05-29: First `../mahjong-t2` probe showed lightweight fallbacks reduced `GameOrchestrator` from 1,120,061 to 1,055,844 optimized TAC instructions with about 1.7s extra local-pass time, and reduced generated bytes from 94.3MB to 86.5MB. Probe also exposed that `NetworkGameOrchestrator` can shrink below 500k and accidentally re-enable SCCP, so heavy pass gates must consider original input size.
- 2026-05-29: Reordered the huge-input path so block-local cleanup runs before SCCP/DataCollection/global passes, and changed SCCP/DataCollection gates to consider original input size.
- 2026-05-29: Removed duplicate local cleanup later in the same iteration when the pre-heavy cleanup already ran. Final `../mahjong-t2` profile completed with rc=0: `GameOrchestrator` optimized to 1,055,844 TAC / 86,524,916 bytes in 42,677.7ms; `NetworkGameOrchestrator` optimized to 477,359 TAC / 40,049,991 bytes in 18,160.3ms; core total 85,976.1ms.
- 2026-05-29: Tried block-local SCCP. Reusing the global SCCP lattice was too slow because alias invalidation rebuilt large reverse maps; replaced it with a simple per-block constant map and kept copy alias handling in `copyPropagationLocal`.
- 2026-05-29: Final block-local SCCP profile completed with rc=0. `GameOrchestrator` optimized to 1,055,724 TAC / 86,578,952 bytes in 44,349.3ms; `NetworkGameOrchestrator` optimized to 477,118 TAC / 40,017,417 bytes in 16,287.6ms; core total 84,946.7ms. - 2026-05-29: Tested limiting `mergeLinearBlocks` rounds inside `simplifyJumps`. It did not improve the final profile: one-round and zero-round variants kept the same output counts but worsened optimizer time versus the block-local SCCP baseline, so the experiment was reverted.
- 2026-05-29: Added an instruction-count gate for the SSA/PRE/GVN window. With `pnpm install` refreshed in `../mahjong-t2`, the cold profile completed with rc=0: `GameOrchestrator` optimized to 1,055,701 TAC / 86,578,699 bytes in 23,934.2ms; `NetworkGameOrchestrator` optimized to 477,087 TAC / 40,017,031 bytes in 8,950.8ms. Core transpile total dropped to 57,469.3ms.

Cold profile kept output counts but worsened `simplifyJumps` totals (`GameOrchestrator` 2,739.3ms -> 2,891.5ms; `NetworkGameOrchestrator` 1,042.9ms -> 1,138.8ms) and worsened `NetworkGameOrchestrator` optimizer time (8,396.1ms -> 8,798.1ms), so the experiment was reverted.

## Decision Log

- 2026-05-29: Continue with local orchestration; no subagents due tool policy.
- 2026-05-29: Adopt cheap-to-heavy staged optimizer ordering for large generated TAC. Heavy global/fixpoint passes should not run just because an early lightweight pass temporarily lowers current instruction count below a threshold.
- 2026-05-29: Accept a small optimizer-time increase versus the first completion-only guard because the generated UASM shrinks by about 7.8MB for `GameOrchestrator` and 2.4MB for `NetworkGameOrchestrator`.
- 2026-05-29: Keep block-local SCCP as a constants-only pass. Copy-chain tracking belongs in `copyPropagationLocal`; full SCCP alias invalidation is not lightweight enough for million-instruction TAC.
- 2026-05-29: Keep the SSA/PRE/GVN instruction-count gate. On the large Mahjong generated TAC, the SSA window was expensive and not providing net output reduction; skipping it for original/current inputs above 500k improved both optimizer time and final TAC/byte counts slightly.
- 2026-05-29: Keep the `narrowTypes` single-pass rewrite because it is semantically equivalent to the previous checks and reduces the large-profile optimizer time without changing generated output counts.
- 2026-05-29: Keep the allocation-free copy-resolution loop. It is semantically bounded by the copy-map size, avoids per-use `Set` allocation in hot local/global copy-propagation paths, and improved the large `GameOrchestrator` profile without changing generated output.
- 2026-05-29: Keep the pending-local-dead-store guard. It only skips use invalidation when there is no pending pure definition to invalidate, so it is semantics-preserving and reduces hot-path scanning.
- 2026-05-29: Keep the combined boolean-negation pass. It preserves the two local rewrites, keeps the standalone exported passes available, and avoids duplicate full-instruction/temp-use scans in the main optimizer pipeline.
